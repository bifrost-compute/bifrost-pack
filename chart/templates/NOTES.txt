{{- if .Values.ray.enabled }}

=== Cluster lifecycle ===

  Bifrost reconciles ONLY the RayCluster/RayService objects it owns: it lists
  by app.kubernetes.io/managed-by=bifrost, so another operator's Ray objects
  in {{ include "bifrost-pack.rayNamespace" . }} are invisible to it and are never reconciled or reaped.

  It does, however, own the tenant NETWORK POSTURE of that namespace — a
  default-deny plus tenant-allow scoped to pods it provisioned, and Pod
  Security Standards labels on the namespace itself. Do not point
  ray.namespace at a namespace another pack owns.
{{- if ne (include "bifrost-pack.rayNamespace" .) .Release.Namespace }}

  The control plane runs in {{ .Release.Namespace }} but provisions into {{ include "bifrost-pack.rayNamespace" . }}. Bifrost's
  own tenant-allow policy admits control-plane traffic to Ray heads only from
  pods labelled bifrost-compute.dev/control-plane=true in a namespace labelled the
  same way. Label the control-plane namespace or the dashboard/jobs/nodes
  proxies will time out:

    kubectl label namespace {{ .Release.Namespace }} bifrost-compute.dev/control-plane=true --overwrite
{{- end }}
